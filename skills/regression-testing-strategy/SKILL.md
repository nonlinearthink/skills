# 项目回归策略

定义项目长期维护的测试资产、回归集合与阶段门禁，是相关规则的唯一来源。单次变更的传播分析、选测与执行使用 `using-regression-testing`。

本 skill 提供共享参考，保持只读。需要盘点、批量处置或写回项目时，由用户显式调用 `organize-tests`；其他流程不自动展开项目整理。

## 事实源与测试资产

优先使用项目原生的用例管理系统、测试代码、需求与发布规则，避免另建无人维护的影子清单。测试地图保存会改变选测决策的信息和稳定定位；可直接从代码与配置查得的长清单留在原处。

每项手工或自动化用例至少能定位到：稳定 ID 或选择器、当前业务能力、前置条件、关键动作、可观察结果、保护的行为与约束、风险依据、执行方式、环境与数据要求、回归层和执行频率。缺失事实标为未知。一个自动化文件可以包含多项用例，一个用例也可以由多个检查共同承接。

盘点和处置时使用 [测试资产清单模板](references/test-case-inventory.md)。

## 用例处置规则

| 处置 | 适用条件与证据 |
| --- | --- |
| 保留 | 仍对应当前产品行为，并保护独立风险或发布决策。 |
| 合并 | 业务路径、可观察结果和判定标准重复；保留项承接原用例独有的角色、数据、错误、权限、时序与恢复约束。 |
| 改写 | 风险仍有效，但步骤、预期、数据或定位方式已经模糊、过时或不可重复。 |
| 调整层级/频率 | 用例有效，但不属于每次发布或每次模块变更都要执行的范围。 |
| 淘汰 | 能力已下线、需求已失效，或覆盖已由其他用例完整承接；记录产品、代码或替代用例证据。 |
| 待审 | 有效性或重复关系无法确认；保留现状，列出需要补充的事实。 |

执行次数少、用例较老不能单独作为淘汰依据。覆盖缺口记为“新增候选”，写明要保护的行为和预期结果；只有任务包含设计或实现时才补入用例库或测试代码。

## 风险与回归集合

沿用项目已有优先级。结合失败后果、历史缺陷、使用频率，以及资金、数据安全、权限、主流程和关键依赖判断风险。风险分数只作辅助，低频不等于低后果。

- **核心回归／最小发布回归集**：覆盖主业务、关键依赖、核心权限与高风险历史缺陷。每项都能说明失败会伤害哪个发布决策，并具有唯一定位；相同覆盖只保留一个稳定入口。
- **模块回归**：按业务能力与契约关联生产方、上下游消费方及实际用例，为单次变更的影响分析提供入口。目录只是线索，不机械等同于模块。
- **全量回归**：项目当前有效、受控的完整用例集，用于约定的发布、定期检查、广泛影响或高影响未知，不作为每次修改的默认集合。

低频稳定项可留在全量或定期抽样；抽样需要固定候选池和轮换规则，抽样结果不能冒充完整覆盖。探索性验证和依赖人工判断的异常场景可作为补充单独标记。

## 阶段门禁与入口出口

按日常修改、普通合并、发布/定期检查分别定义必需回归集合、升级全量条件和例外批准来源。日常修改通常覆盖直接影响与受影响消费方；合并和发布按项目策略叠加核心或全量门禁。门禁独立于单次影响面结论，既有更严格要求继续有效。

回归入口记录改动说明、影响模块、公共组件、数据库/配置/权限/开关、回滚方式，以及版本、环境、依赖服务、测试数据、账号和权限是否就绪。局部开发检查可以先完成可行部分，但不能冒充正式回归完成。

回归出口记录必须通过的核心项、必须拦截的问题、可接受残余风险的批准来源和必要证据。真实外部服务、真实平台、安装与分发等验证保持独立，缺什么就报告什么。

回归范围与单元、接口、浏览器、数据库、跨进程等执行方式分别定义；核心行为也可能需要集成证据。

## 执行与自动化策略

为常规回归集记录稳定选择器、执行命令、选择核对方式、必要前置、数据与账号要求、共享资源限制和结果复用条件。只有数据、账号和输出互不污染时才并行。单次变更如何组合筛选并核对实际选择，由 `using-regression-testing` 处理。

自动化候选优先满足高频执行、路径稳定、动作重复、结果判定清晰，并且环境与数据可控、维护成本低于重复执行成本。界面频繁变化、规则持续调整或依赖人工判断的用例优先保留人工或探索性验证；自动化建议不等于实施。

## 项目测试地图与维护

建立或更新地图时使用 [项目测试地图模板](references/project-test-map.md)。地图至少包含阶段门禁、固定核心清单、模块传播入口、命令与执行约束，以及未确认策略和例外批准来源。

核心选择器、业务边界、测试路由或发布策略改变时同步地图。新增核心候选先检查既有覆盖，防止核心集膨胀；模块地图不把“改某个目录”机械等同于“跑整模块”。

## 效果评估

评估优化效果时，分别记录准备、执行、阻塞等待、复测和清理耗时，比较回归总历时与阻塞时间占比，并在同等发布频率下观察漏测和线上回归缺陷变化。没有基线或后续数据时，只报告当前用例数量、覆盖结构和已执行事实，不宣称质量不降或效率已经提升。
