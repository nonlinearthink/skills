# octo-mode

接收目标，负责选择方法、衔接阶段并推进到已授权的交付终点。用户决定产品和验收，入口承担流程选择。面向 Codex 与 Claude Code；同一任务的后续消息沿用当前状态，范围变化时重新选路。

## 接入任务

1. **确定意图与终点。** 明确实施请求进入开发闭环；“先分析”“只设计”“只审查”保持该边界。默认开发终点是已验证、独立审查的 PR；用户指定本地修改、补丁或其他终点时以其为准。合并、部署和客户消息分别需要已有授权，不能从开发目标推导。
2. **读取当前证据。** 查目标仓库的指导文件、当前分支与工作区、已有需求和相关实现、验证入口。记录任务开始时的 commit、工作区已有改动及归属；仅把本任务改动纳入提交。已有 glossary、ADR 和任务决定按需复用。
3. **形成最小简报。** 记下目标、可观察的验收、范围、交付终点与未决决定。小任务放在当前上下文；复杂、长时间或多人执行时保存到已有任务记录，或临时目录中的任务专属文件。已有 spec 用指针，避免重复真相来源。
4. **只问阻塞决定。** 自查事实，自选可逆的实现和测试边界。缺失的产品含义、验收要求或不可逆取舍，先给推荐与影响，再向用户提问；继续独立工作，答案到达后再做依赖该答案的部分。完整 grilling 只在明确要求深挖时启用。

完成条件：能说明做成什么、如何判断，以及哪些工作已经授权。技术未知可以成为调查步骤；未答的业务决定保持未决。

## 自动选路与加载

读取 [路由与阶段协议](references/workflows.md)，选择满足目标的最短路径，并把实际需要的步骤放入工作清单。小改动直接实现；依赖图只用于确有多个可验证单元的任务。执行中出现新证据时调整路径，不要求用户重新发送下一条 skill 命令。

开始使用 Matt 方法前读取 [上游适配规则](references/upstream.md)。按该规则定位并读取本次需要的源文件及被触发的支撑材料；它们决定工程方法，本入口决定阶段、澄清强度和交付边界。无需扫描或加载全部上游 skills。

辅助定位命令（将尖括号路径换为实际路径）：

```bash
python3 <octo-mode目录>/scripts/resolve_matt.py --project <目标仓库> tdd code-review
```

宿主已提供的 plugin/skill 绝对路径优先使用；脚本支持 `--root <技能目录或上游checkout>`。输出包含来源路径及与适配基线的差异。依赖缺失和版本漂移的处理见适配规则。

## 推进执行

- **每个单元有完成判据。** 先满足该单元的行为和检查，再推进依赖它的工作。缺陷先得到针对原症状的失败信号；功能按可观察行为逐片实现；重构保留原行为的证据。
- **按独立性委派。** 有可并行且写入互不重叠的工作时，使用宿主原生子代理；共享代码依次集成。复杂依赖图按 `implement-spec` 的 frontier 思路推进，详见阶段协议。主代理负责目标、集成和最终质量。
- **传递可执行上下文。** 委派时提供本 skill 的绝对路径、所需适配规则、简报/spec 指针、任务、允许写入范围、基准和完成判据。使用新上下文，不把调试猜测当成审查结论传给独立审查者。
- **避免空转。** 检查失败先保留证据、判断原因，再采取不同且有依据的下一步。同一阻塞经两次有差异的修复仍无进展，重新检查前提、缩小复现或换方法；只有确实需要用户信息或外部状态变化时交接，记录下一项可解除阻塞的动作。
- **保持任务可接续。** 长任务在完成单元、变更决定或遇到阻塞时更新简报、当前代码标识、验证和下一步。接续时读取记录并核对实际仓库，复用仍有效的证据。

## 验证、审查与交付

进入此阶段前读取 [质量与交付闭环](references/finish.md)，按影响选测，独立审查完整任务变更，修复后复核，再交付。审查和测试都必须明确所覆盖的代码；完成以后发生新改动，要更新失效证据。

保持在当前任务中推进，直到满足已授权终点，或有可说明的真实阻塞。宿主不支持子代理时可串行实现，但自审须标为自审，独立审查缺口保持打开。Markdown skill 不提供进程守护、自动唤醒或跨进程自动恢复。

最终给出结果、验证与审查证据、PR/产物位置以及剩余缺口。只调查/设计/审查的请求在其对应产物完成后结束。
