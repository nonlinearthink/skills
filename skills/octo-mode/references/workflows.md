# 路由与阶段协议

本文件是 `octo-mode` 自己执行的阶段协议。规划与协调方法改编自 Matt 的 `to-spec`、`to-tickets`、`implement`、`implement-spec`；上游对应入口仍可由用户单独使用。

## 按意图选择路径

| 当前目标 | 路径 | 按需读取的 Matt 方法 | 终点 |
| --- | --- | --- | --- |
| 解释代码、调查原因、评估方案 | 调查 → 证据与未知 | 需要运行复现时 `diagnosing-bugs`，需要领域/接口判断时对应设计方法 | 有来源的回答；仓库与远端只读 |
| 只做设计/计划 | 调查 → 必要澄清/实验 → 方案与验收 | `codebase-design`、`domain-modeling`，纸面无法判断时 `prototype` | 设计产物；按请求保存，实施另需授权 |
| 只做审查 | 固定范围 → Standards/Spec 独立审查 → 报告 | `code-review` | 审查报告；修复仅在原请求也要求时继续 |
| 修复缺陷/性能退化 | 复现原症状 → 定位根因 → 最小修复 → 原复现与回归 → 审查 → 交付 | `diagnosing-bugs`，适用时 `tdd` | 已指定的开发终点 |
| 明确的功能 | 调查 → 最小简报 → 行为切片实现 → 验证 → 审查 → 交付 | `tdd`，必要时设计方法 | 同上 |
| 保持行为的重构 | 固定行为与调用方 → 调整结构 → 契约/回归验证 → 审查 → 交付 | `codebase-design`、适用时 `tdd` | 同上 |
| 多单元/已有 spec 和 tickets | 读完整需求与依赖 → frontier 协调 → 集成验证 → 总审查 → 交付 | 各单元按上面的实际目标加载 | 同上 |
| 模糊的大目标/没有合适路径 | 先调查最大未知 → 问阻塞验收决定 → 形成可验证单元 → 执行对应路径 | 仅加载解决当前未知所需的方法 | 收敛到目标；遇到真实未决决定可交接 |
| 接手续做 | 读简报、分支、当前工作区和已有证据 → 核对未完成单元 → 继续其路径 | 不重做已完成且证据仍有效的阶段 | 沿用原终点与授权 |

调查中的 probe 使用临时目录；只读请求不借调查写入目标仓库、开 issue、提交或 PR。设计所需的原型只在设计请求允许的范围内创建。

## 最小简报与按需规格

用现有需求回答：问题是什么，完成后观察到什么，哪些约束继续成立，如何验证，什么不在本次范围。已确认的决定直接复用。

仅当单份简报不足以协调或验证时，扩展为 spec 和任务图：

- Spec 保留问题、用户可见行为、实现约束、验证决定和范围。叙述长度由需求决定。
- 单元是可验证的纵向行为切片，每项写明验收、阻塞项和状态。
- 技术事实和可逆的拆分由代理调查、决定；影响产品/验收的分叉交用户。
- 读已有 tracker 配置；无配置时使用本地记录，不把 setup 访谈作为开始实施的门槛。
- 发布新远端 tickets、改标签或关闭 issue，仅按用户或项目已有授权执行。本地任务图足以协调时无需发票。

此阶段结束于验收足以执行、单元的真实阻塞关系明确；不是生成了某份固定模板就结束。

## 单单元实现

从现有代码约定选择最小实现。需要行为测试时，选择调用者实际经过的公开边界，按 red → green 的纵向切片工作；低影响且可逆的纯文案/样式调整可以使用直接检查或真实界面验证。项目要求的测试始终执行。

领域词义冲突才加载 `domain-modeling`；接口或可测试性有实际设计问题才加载 `codebase-design`。不为阶段完整而创建 glossary、ADR 或抽象。

缺陷保留原始复现与修复后的对照；性能工作先测基线，再用相同条件比较，避免只报告数值而没有测量对象。

## 多单元协调

1. 核验任务图：每项验收可检查，所有阻塞项存在，依赖无环。已有问题先解决再调度。
2. 复用已指定分支；需要隔离时从任务基准创建专属 integration branch。记录来源，保护已有工作。
3. 只领取阻塞项全部完成的 frontier。小任务或不能隔离的改动串行；独立单元可在宿主允许的并发范围内委派。
4. 并行写入使用独立 worktree/branch；worker 先核对基于 integration branch 的当前版本。主代理或单一集成者按依赖顺序集成，解决冲突后验证。禁止多个代理并发修改同一工作区。
5. worker 返回改动标识、验收、真实检查输出与未决项。集成后的代码通过该单元检查才标完成，再更新 frontier。单元完成不代替整体验收。
6. 对最终集成结果运行质量闭环。仅清理本任务且已安全集成、无独有未提交工作的 worktree。

宿主无子代理/worktree 能力时依次执行同一图；不能把串行或自审描述为已经并行或独立验证。

## 停止与接续

修复循环的退出条件是验收与所需检查通过，或已经识别出无法在现有授权/环境内消除的阻塞。交接记录包含：目标与终点、基准/当前分支和代码、完成与待办单元、有效及失效证据、未决问题、下一步。凭据只留环境变量名或安全来源指针。

新消息是当前任务的补充时更新简报，不重新启动整条流程；用户明确更换目标才建立新任务。接续记录必须和当前仓库对照，不能把记录中的“已完成”当成当前事实。
