# 变更影响面与回归选测

把完整变更转换成有依据的测试计划：每项改变的行为和受影响的约束都有验证；传播在有证据的边界停止。输出可执行命令、选择理由和证据缺口，按任务授权执行。

## 读取项目约定

先查仓库指南、测试地图、包脚本和测试配置。遵循用户及项目已有的验证要求；本 skill 不自动豁免全量、发布或外部操作规则。任务只要求分析时，交付计划；要求实现或验证时，继续执行所需检查。

区分两个维度：

- **范围**：核心回归是固定的精简关键行为集；模块回归是本次改变的行为及受影响消费方；全量回归是项目约定的完整受控测试集。
- **执行方式**：单元、浏览器、数据库、跨进程、运行时和安装包等。按要验证的边界选择方式；核心行为可能需要集成测试。

项目没有测试地图时，从实际代码、测试和任务配置推导本次计划，说明尚未确认的核心清单。任务包括建立地图时，使用 [项目测试地图模板](references/project-test-map.md)，把项目路径和命令留在仓库中。

## 分析行为传播

1. **固定范围与基准。** 使用用户指定的比较点；分支审查通常使用与目标分支的 merge-base，单次修改可用工作区开始前的状态。纳入范围内提交、暂存、未暂存、新增和删除文件；有并行工作时分别标明归属及运行时实际包含的改动。记录基准和当前状态，避免只看最新 commit 漏掉累计变更。
2. **描述改变的行为。** 从需求和 diff 提取输入输出、错误结果、权限/租户归属、数据约束、事务、时序、事件、持久化、恢复及构建运行行为的变化。行为保持不变的重构也要说明需要继续成立的约束。
3. **追踪生产方与消费方。** 查直接调用方，再逐层判断改变是否传递。除 import 外，检查实际存在的 HTTP、IPC、事件、共享存储、配置、生成代码、资源、提示词/skills 与进程或产物边界。依赖图和历史覆盖只能提供候选；既要检查读方，也要检查会生产新输入的写方。
4. **给出停止边界。** 对每条传播路径说明下一层依赖的行为为何保持成立，并指出代码、契约或边界测试证据。签名相同不代表权限、顺序或失败语义相同；被依赖也不意味着所有行为均受影响。删除、改名时结合基准版本查旧调用和测试。
5. **处理未知。** 先调查缺失的边或契约。调查后仍无法限定范围时，扩大到可能受影响的模块；若跨领域传播仍无法限定，按项目规则升级全量，并报告未解决的原因。没有对应测试时补充有效回归或明确记录缺口，不能把“未选到测试”记为验证通过。

范围与后果分别判断：影响几个消费方决定覆盖广度；失败会违反哪些关键约束决定验证深度。局部发送授权修改可能需要深入验证重放与恢复，多个页面的独立文案修改仍可局部检查。文件数量、目录数量和风险打分不能单独决定全量。

## 形成并执行测试计划

按项目阶段策略取集合的并集，重叠测试只执行一次：

- 开发中运行直接相关回归；普通合并通常选择核心 + 模块回归。
- 全量用于项目约定的发布/定期节点、明确要求，或已确认的广泛影响。公共权限、事务基础设施或运行机制的广泛语义变化、大规模架构调整是升级信号；具体触发条件由项目地图定义。
- 纯说明文档且不影响程序/Agent 行为时做文档检查。被程序或 Agent 消费的配置、提示词和 skill 要按实际消费关系判断，不能仅按扩展名免测。

对每项受影响行为，选能观察真实边界的最低必要成本检查；需要数据库或跨进程语义时保留该层证据。类型检查、生成代码一致性、构建/任务图检查按改动另选，不能代替运行行为验证。每个被选文件或用例都要能说明覆盖什么；核心集的固定选择理由由项目地图提供。

检查脚本和配置，确认命令实际选中了计划中的测试，保留构建等必要前置。可用 runner 的 list/dry-run 核对文件和用例。遇到无匹配或空结果先调查路由，不把成功退出视为覆盖成功。

合并同一 runner 的重复选择时注意文件筛选与名称筛选的组合语义：核心使用 `-t`、模块需要整文件时，直接把文件拼接后沿用核心 `-t` 会漏掉模块用例。让模块完整范围优先，必要时分开执行并消除重叠。成本判断同时考虑构建、数据库、应用启动、测试执行和清理，不以单个用例时长代替整条命令成本。

相关代码、依赖、配置、测试和环境未变且已有可定位证据时复用结果；新改动后只重跑证据失效的范围。失败时保留首次证据并调查原因，不能反复重跑直到绿灯后隐藏失败。满足计划且没有新改动、失败或未解疑点时停止验证。

## 交付证据

小改动用几句话，复杂变更用表格。至少说明：

- 比较基准、工作区范围及改变的行为。
- 受影响消费方、停止传播的依据、选择的回归范围及全量触发理由（如有）。
- 命令与实际选择/执行结果；尚缺的测试或环境证据。

区分“计划”“仅核对选择”“实际通过”“未执行/失败”；受控回归、真实外部服务、真实平台和分发验证分别报告。未测量前不承诺耗时预算或提速比例。
