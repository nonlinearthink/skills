# UI design

让用户看清状态、找到下一步并完成任务。视觉设计应体现具体产品的特点。

## 确定任务与范围

- 明确产品主题、使用者、当前状态、要完成的任务和成功结果，据此选择展示的信息与操作。
- 参考用户提供的设计和现有相邻页面。局部修改聚焦受影响的组件与流程，沿用已有组件、视觉规范和业务术语；新增页面也应融入现有产品。
- 技术实现遵循目标目录的 `AGENTS.md` 及相关框架、组件库约定。

## 确定视觉方向

建立或重做视觉风格时，先形成简短方案，检查其符合需求后再实现。用户明确的风格要求优先。

- **主题与重点**：从产品的行业、素材和使用场景提取视觉线索，集中一个主要视觉重点，周围保持清楚、克制的层级。
- **色彩**：先确定背景、文字、强调色和状态色的职责，再选择具体色值；让配色服务内容、品牌与状态识别。
- **排版与布局**：字体兼顾产品气质、目标语言的字形覆盖与阅读场景。用少量有明确分工的字体，统一字号、字重、行高与间距，按语言和设备调整行宽。需要比较空间关系时画简略线框。
- **针对性**：只替换产品名称和图片，方案是否仍能原样用于任意产品？若是，重新检查视觉选择与内容的关系，让常见配色、卡片或渐变也有符合本次需求的用途。

## 组织布局与交互

- 用真实或贴近业务的标题、图片和数据推敲布局，让内容的长度、数量和含义参与设计。
- 通过位置、分组、间距和视觉权重建立信息层级。任务流程突出当前步骤和主要操作；后台列表保留便于查找、比较的数据；展示型页面用有代表性的内容建立首屏识别。
- 按用户执行顺序组织表单与操作。需要反复解释的流程，先检查控件命名、默认值、分组和顺序。
- 按信息关系选择容器。卡片、边框和徽章用于分组或表达状态，序号用于确有顺序含义的内容；简单内容可直接排版。
- 保持可读字号、足够的对比度和触控空间，保留键盘操作与可见焦点。用内容取舍和布局调整减轻拥挤。
- 用动效解释展开、切换、确认等操作带来的变化。自动动效仅用于必要的注意力引导，集中安排，并尊重系统的减少动态效果设置。

## 编写文案与状态反馈

- 使用用户熟悉的业务语言，每段文字承担识别、决策、操作或结果解释中的明确用途。删除重复标题、复述按钮的说明和空泛宣传语；技术细节仅在帮助决策或解决问题时展示。
- 操作文案直接说明结果，例如“保存修改”；同一动作在按钮、确认弹窗和结果反馈中保持一致的名称。
- 保留字段标签、格式要求与必要指引，放在对应字段或操作附近。低频补充内容可折叠或通过帮助入口查看；相关费用、限制、前置条件和重要后果在确认操作前直接可见。
- 按需覆盖本次改动涉及的加载、空数据、成功、失败和不可用状态。空状态说明情况并给出适用的下一步；失败反馈说明发生了什么和恢复方法；不可用操作在附近说明解除条件。

## 验证实际效果

- 从用户视角走通受影响的主要路径，确认状态清楚、下一步可发现、错误可恢复。
- 使用可用的浏览器预览验证实际渲染与交互，按使用场景检查窄屏、长内容、相关状态和键盘操作。文案修改检查换行与布局。
- 结合截图审视层级、排版、配色和视觉重点，修正偏离需求的地方。精简没有明确用途的装饰与说明后，确认必要信息与操作仍可发现。
- 报告实际完成的验证；无法预览时说明尚未验证的视觉或交互部分。
