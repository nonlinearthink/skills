# 测试园丁：用例盘点与分层

把现有手工和自动化用例整理为反映当前产品风险的受控集合：每项用例有有效性和处置结论，每项关键风险有可定位的覆盖，形成去重后的最小发布回归集。顺序是先盘点、再分层、最后评估自动化；目标不是删除数量或自动化率。

本 skill 维护用例库和回归集合；单次代码改动的传播分析、选测与执行属于回归选测任务。

## 1. 确定盘点边界与事实源

先读项目指南、现有用例库、测试文件与配置、当前需求和发布规则。优先在项目原生测试管理系统、文档或测试代码中整理，避免另建一份无人维护的影子清单。

明确本次覆盖哪些产品能力、手工/自动化用例和存储位置。外部用例库或历史记录不可访问时，只盘点实际可读范围并列出缺口，不把推测写成已有覆盖。

区分“只盘点”和“写回用例库”。用户要求整理但未限定产物时，先交付可审查的处置清单；删除或批量改写前取得确认。事实不足的项目标为待审，不靠猜测清理。

完成标准：盘点范围、当前产品能力、事实源、不可访问信息和允许写回的范围都明确。

## 2. 建立完整用例清单

使用 [测试园艺清单](references/gardening-checklist.md)，按项目需要裁剪字段，但至少保留：

- 稳定 ID、文件/套件路径或可复选用例选择器。
- 当前业务能力、前置条件、关键动作和可观察结果，而不只抄用例标题。
- 所保护的业务约束、风险依据、现有执行方式和环境/数据/账号要求。
- 当前优先级、回归层级、最近缺陷或执行证据；没有数据就标未知。

自动化测试按实际断言保护的行为归纳，不把“一个文件”机械当成“一个用例”，也不把多个不同断言无依据合并。

完成标准：盘点范围内每项用例都有记录；每条当前核心业务链路都有覆盖定位或显式缺口。

## 3. 逐项给出处置

为每项用例选择一种处置并记录理由：

- **保留**：仍对应当前产品行为，且能保护独立风险或发布决策。
- **合并**：业务路径、可观察结果和判定标准重复；保留项必须承接被合并项独有的角色、租户、数据、错误、权限、时序或恢复约束。
- **改写**：风险仍有效，但步骤、预期结果、数据或定位方式已经模糊、过时或不可重复。
- **调整层级/频率**：用例有效，但不属于每次发布或每次模块变更都要执行的范围。
- **淘汰**：对应能力已下线、需求已失效，或覆盖已由其他用例完整承接。记录产品/代码证据或替代用例 ID；执行次数少、用例较老不能单独作为淘汰依据。
- **待审**：无法确认有效性或重复关系，保留现状并列出需要谁提供什么事实。

覆盖缺口单独记录为“新增候选”，写明要保护的行为和预期结果；只有任务包含设计或实现时才补入用例库或测试代码。

完成标准：每项已盘点用例都有处置和证据；每项合并/淘汰都能证明没有丢失独特约束，不能证明的保持待审。

## 4. 标记风险、优先级和回归层

沿用项目已有优先级。判断时结合功能影响范围、历史缺陷密度、用户访问频率、资金/数据安全等级，以及主流程、关键依赖和核心权限受损后的后果。风险分数只能辅助，低频不等于低后果，关键资金、数据和权限约束不能仅因访问量少而降级。

将有效用例组织为三层：

- **核心回归／最小发布回归集**：覆盖主业务流程、关键依赖、核心权限与角色、高风险历史缺陷。每项都要回答“失败会伤害哪个发布决策”，相同覆盖只保留一个稳定入口。
- **模块回归**：按业务能力和契约关联模块及其上下游消费方，作为变更影响分析的入口，不把目录机械等同于模块。
- **全量回归**：由当前有效、受控的完整用例集构成，用于项目约定的大版本、底层重构、架构迁移或高耦合调整，不作为每次修改的默认集合。

低频稳定项可留在全量或定期抽样；抽样要有固定候选池与轮换规则，结果不能冒充完整覆盖。探索性验证和依赖人工判断的异常场景可作为补充单独标记，不挤占核心集。

完成标准：每项有效用例都有优先级、回归层和执行频率；每项核心用例有发布风险理由与稳定定位，每个模块入口能定位到实际用例。

## 5. 评估自动化与执行准备

自动化候选优先满足：**高频执行、路径稳定、动作重复、结果判定清晰**，并且环境和数据可控、维护成本低于重复执行成本。核心接口连通、主流程冒烟、关键字段校验和固定业务规则通常是候选；仍以项目事实判断。

界面频繁变化、规则经常调整或依赖人工判断的用例优先保留人工/探索性验证。自动化建议不等于实施，只有任务要求时才编写或迁移脚本。

为核心和模块集记录环境模板、依赖服务、标准数据、角色账号、恢复方式、责任归属及共享资源约束。可以并行执行的前提是用例边界和结果记录清晰，并且数据、账号和输出互不污染；未知归属或不可隔离项列为准备缺口。

完成标准：每个自动化候选都有收益与维护依据，每个常规回归集都有可核对的准备条件和并行边界或缺口。

## 6. 写回并交付审计结果

按授权写回项目原生事实源；任务包含测试地图时，同步核心清单、模块入口和执行命令。保留原 ID 到新 ID、合并或替代用例的追踪关系。

交付至少包括：

- 盘点范围，以及保留、合并、改写、调整、淘汰、待审和新增候选的数量与明细。
- 最小发布回归集、模块索引和全量边界。
- 合并/淘汰的覆盖证明、仍未覆盖的风险和准备缺口。
- 自动化候选与保留人工的理由；实际写回位置或“仅建议，未修改”。

若优化效率，先记录当前准备、执行、阻塞等待和复测耗时，再用后续轮次比较回归总历时、阻塞时间占比及同等发布频率下的回归缺陷变化。没有这些数据时，只报告用例数量和覆盖结构变化，不宣称质量不降或效率已经提升。
