# 开发 skills 设计讨论

状态：仓库定位已调整，按功能组讨论取舍中。更新于 2026-11-16。

## 目标与定位

以 [mattpocock/skills](https://github.com/mattpocock/skills) 为基础进行补充，让完整开发流程更自动化、更好用。上游继续提供工程方法与质量纪律；本仓库优先补充统一入口、自动选路、阶段衔接和其他上游未覆盖的专用能力，而不是另建一套平行体系。

[cursor/plugins/pstack](https://github.com/cursor/plugins/tree/main/pstack) 保留为自动化机制的参考，例如统一路由、完成判据、验证和恢复协议，不再与 Matt 并列为新套件的基础，也不要求整套移植。

目标是自动生产高质量代码，并在无人值守时继续开发。默认终点、首版范围和澄清强度沿用下方已经确认的决定。

2026-11-16 用户明确定位：“这套 skills 的目标是在 mattpocock/skills 的基础上，进行补充，让整个流程更加自动化、好用。”此决定取代早期将 Matt 与 pstack 作为两个并列来源再决定组合方式的候选方向；已有调研继续作为历史证据和具体方法来源。

早期调研通过用户显式调用的 `grill-with-docs`，结合 `grilling`、`domain-modeling` 和源码调研推进。研究不构成删除、替换、安装现有 skills 或执行开发任务的授权。

## 第二轮已确认

用户答复：“Q3、Q4、Q5都同意”。

- **Q3，交付边界：** 两档交付，默认实现、验证、独立审查和修复后交付 PR；项目或任务明确授权时自动合并。部署未纳入此次决定。
- **Q4，无人值守范围：** 首版覆盖用户启动的一项任务持续推进；跨进程自动恢复与事件驱动自动接单留待后续。此决定不取消首版任务中必要的进度、证据与交接记录。
- **Q5，澄清强度：** 常规开发仅追问缺失的产品/验收决定和不可逆取舍，事实自行调查、可逆实现自行选择；完整 grilling 仅在用户明确要求深挖时启用。

## 当前组待决

- **Q6，入口触发：** 是否让明确的仓库开发请求自动进入统一入口，同时保留显式快捷调用？建议采用；“问用法/只讨论/只审查”分别保持其意图。
- **Q7，澄清产物：** 是否按任务规模复用或记录一份最小任务简报，仅在新术语/重要取舍/复杂工作需要时扩展 glossary、ADR 或完整 spec？建议采用，不固定要求每个小改动新建文档和发票据。

该组具体保留、合并与移除独立入口的建议见分组文档，尚未视为已接受。
