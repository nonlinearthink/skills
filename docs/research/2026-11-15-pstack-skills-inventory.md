## 结论与边界

pstack 值得借鉴的是“先定义可证伪完成条件、把任务拆成可验证单元、作者和验证者分离、运行真实产物、记录决策、按失败原因恢复”这一整套执行协议。它主要由给模型阅读的指令构成，不能等同于有持久调度、权限隔离、强制 gate 和进程恢复能力的完整运行时。建议采用其协议核心，按仓库和宿主重写路由与执行层，再逐个引入高成本能力。该建议尚未与用户确认，本文没有修改任何现有技能。

## 自动路由与分工实际怎样发生

1. **入口需要先加载。** `setup-pstack` 可按用户语义触发；其余 57 个正常技能默认由用户显式挂载，或由已经加载的 mode 按路径读取。它们的 description 不是运行时 dispatcher。`poteto-help` 明说安装本身不启动工作，普通 slash Enter 也不会永久保留 mode。[poteto-help](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-help/SKILL.md)、[poteto-mode](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/SKILL.md)。
2. **路由是模型遵循文字规则。** mode 覆盖调查、缺陷、性能、特性、重构、原型、自治、交付等场景；大任务可转 figure-it-out，项目级长项目可转 orchestrate。没有发现用于任务分类的确定性 router、hook 或服务。[poteto-mode](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/SKILL.md)、[figure-it-out](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/figure-it-out/SKILL.md)。
3. **组织工作靠 Task 和宿主。** 普通 playbook 子代理必须用 poteto-agent，它先全文读 mode；arena/swarm/interrogate 等专门技能可指定 generalPurpose。默认后台运行、隔离 worktree 或 cloud VM，父代理对结果负责。[poteto-agent](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/agents/poteto-agent.md)、[swarm](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/swarm/SKILL.md)。
4. **不是默认无限并行。** Feature 要说明 blocking prerequisite、独立工作、共享可变状态和最小拆分；代码耦合任务给一个 owner。Orchestrate 先跑一单元，最多三层协调结构、每 coordinator 约十 worker。确定性 codemod 优于让一群 agent 手改。[feature](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/feature.md)、[orchestrate](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/orchestrate.md)、[principle-build-the-lever](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/principle-build-the-lever/SKILL.md)。
5. **模型选择可配置且硬绑定 slug。** 当前 code/prose/judgment 默认 `claude-opus-5-5-xhigh`，最难任务 `claude-fable-5-2-max`；panel 默认 Fable/Opus/Gemini 三席。setup 写 13 个角色配置并按预算调 effort，arena judge 尽量使用不同 vendor。源码提供被拒 slug 的 fallback，但这不是证明任何其他宿主有这些模型。[setup-pstack](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/setup-pstack/SKILL.md)、[arena](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/arena/SKILL.md)。

## 验证、review 与真正的强制边界

| 机制 | 文字协议要求 | 可执行实现与局限 |
|---|---|---|
| 开始前定义 done、每步真实验证、父代理审 artifact | mode、figure-it-out、原则都要求 | 没有共通 runner 强制每步；依赖模型实际执行 |
| 作者与 verifier 分离 | orchestrate 每 PR 非作者且不同模型；shipping 每 PR 非作者 | 没有代码证明 verifier identity 或阻止作者越权 merge |
| adversarial review | interrogate 多模型运行复现，父代理重跑，只留可证实 finding | 是流程；对不可运行的静态风险、规范差异、未来路径风险会偏严格过滤，不足以替代 standards/spec review |
| unit/live/perf 验证 | multi-phase plan 每 PR 十条 live lane、unit、perf | `check-plan.mjs` 会检查文档模板和 lane 数、截图/Pass when 标记；**不执行这些验证，也不确认结果真伪** |
| PR merge-readiness | babysit 优先 conflicts→threads→CI | `watch-pr` 是真实的只读 forge 状态程序；不修复、不 review 产品行为、不 merge |
| 决策日志 | 长任务逐轮 append、transcript 对账与跨模型审阅 | `log.sh` 真正做 TSV 清洗和 append；不校验证据存在，不强制单写者/锁，也不保证语义真实 |
| 技能和脚本上游 CI | validate plugins、生成 harness 同步、skill script tests | 是 cursor/plugins 自身 CI，**不会被安装到下游项目变成其强制 gate** |

## 循环、故障恢复和停止线

- **循环主体和唤醒是两回事。** Autonomous run 写的是每轮假设→最小改动→真实验证→keep/revert→checkpoint。能在 turn 结束后再唤醒它的是 Cursor 内建 `/loop` 或宿主 event watcher；pstack 没有自己打包 `/loop` skill、daemon、crontab 或 durable queue。移植时只复制 Markdown 不会获得 overnight 持续工作能力。[autonomous-run](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/autonomous-run.md)、[poteto-help](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-help/SKILL.md)。
- **全自动不等于永不停止。** Autonomous run 完成谓词 met 或 genuine dead end；plateau 本身不停止，也不能放松目标。Hillclimb 则允许在剩余收益不值得成本时停止，且目标包含最少尝试次数。Orchestrate 对一个 unit 重试两次后重规划。Benny 有预算/拒绝窗口。各循环停止规则不能混用。[autonomous-run](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/autonomous-run.md)、[hillclimb](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/hillclimb.md)、[orchestrate](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/orchestrate.md)。
- **明确的重试策略。** Swarm 结果漏 SHA/方法只补一次，仍漏标 gap；CI flake 只给一次 fresh build，相同第二次失败重分类；autopilot 根据 push/决策日志而非 status 文字判断 stalled，用新 worker 替换。模型 slug 拒绝有多级 fallback，但不是所有 lane 都能保留真正跨模型独立性。[swarm](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/swarm/SKILL.md)、[babysit](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/babysit.md)、[autopilot-full](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/autopilot-full.md)、[arena](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/arena/SKILL.md)。
- **后台 watcher 是程序，但不是完整 agent supervisor。** watch-pr 会等待 check 状态并输出 terminal verdict；默认无 timeout，只读 forge，不改变代码和合并。Babysit 要 outer `/loop` rearm；shipping 的 queued watcher 才等 merged COMPLETE。不同 forge 的 merge-ready 停止条件也不同。[watch-pr CLI](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/scripts/watch-pr/cli.ts)、[babysit](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/babysit.md)、[shipping](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/shipping.md)。
- **缺少共通硬预算。** setup 的 budget 只调整 reasoning effort，不是 token/美元/并发/总时间硬上限。Autonomous run 鼓励不断 pivot，且中途发现的 related bug/技能/tooling 问题也自己开独立 PR 修；没有全局重试/范围/花费阈值，容易长时间扩散。建议为自建流程另设总时间/总 token 或费用/迭代/无进展轮数，以及 side quest 范围。[setup-pstack](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/setup-pstack/SKILL.md)、[autonomous-run](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/autonomous-run.md)。

## 跨会话状态、权限与提交合并

跨会话信息主要留在 branch/pushed commits、PR/CI、Project `notes.md`/agent store、append-only TSV 与本宿主 transcripts；显式暂停再写 WIP commit 和 `/tmp` resume note。它们有良好的人工接手习惯，但没有一个统一、版本化、原子事务式 run-state schema 或自动重启协议。Session pickup 同时要求尊重前任 trail 并核验继承 claim 的真实产物，设计时应区分“不要重做已完成工作”和“不能把旧自报当现时正确证明”。[session-pickup](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/session-pickup.md)、[pause-safely](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/pause-safely.md)、[orchestrate](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/orchestrate.md)、[show-me-your-work](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/show-me-your-work/SKILL.md)。

权限不能原样继承。mode 的 Autonomy 段把任意 MCP、team chat、ticket updates、eval 等外部可逆写看成无需询问；leaf never-block 则把外部消息列作需确认，形成不一致。Reflect 自动写团队 backlog；Benny 又对每次源线程写做严格防护。自建流程必须有一个权威授权表，区分本地写、commit、push、PR、评论/消息、merge、deploy、数据删除，明确用户已有授权范围，不把“在 skill 里说了”当用户授权。[poteto-mode](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/SKILL.md)、[principle-never-block-on-the-human](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/principle-never-block-on-the-human/SKILL.md)、[reflect](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/reflect/SKILL.md)、[Benny triage](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/automations/benny/skills/triage-issue-reports/SKILL.md)。

提交/合并默认相当积极：普通代码 playbook 会走 ready PR；opening-a-pr 建议 liberally commit、amend/rebase、小 PR；pause 会自动 WIP commit；autopilot 早 push；shipping 会 squash merge、自底向上重定 base 与 force-with-lease。Babysit 则明确到 merge-ready 为止，查状态不等于 merge 授权。默认 ready PR 与 Benny draft-only 属于不同 workflow，不能抹平。[opening-a-pr](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/opening-a-pr.md)、[pause-safely](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/pause-safely.md)、[autopilot-full](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/autopilot-full.md)、[shipping](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/shipping.md)、[babysit](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/babysit.md)。

`opening-a-pr` 的隔离/恢复建议还出现 reset-hard、worktree 重建等命令；worktree-cleanup 把 untracked 全归 scratch 并允许 force remove/rm，未必适合含未跟踪用户文件的仓库。这里不是要求执行这些操作。建议只采纳“隔离工作区/独占写入/先观测后清理”，破坏性恢复与清理保持独立明确授权。[opening-a-pr](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/opening-a-pr.md)、[worktree-cleanup](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/worktree-cleanup.md)、[audit script](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/scripts/worktree-audit.sh)。

## 对自建开发 skills 的初步建议

以下是后续共创的候选，不是本次安装或修改决定。

| 取舍 | 建议内容 | 理由 |
|---|---|---|
| 优先采纳 | repo 可执行 verify skill、done predicate、同面复现/前后证明、行为测试、独立 reviewer、SHA 绑定的 verdict、按单元验证 | 直接帮助代理判断是否完成，减少自报正确 |
| 合并提炼 | how+why→understand；blast-radius+interrogate→review 的不同 lens；目标复述+ketchup→沟通；show-me-your-work+pickup+pause→checkpoint | 减少重叠和每回合多技能开销，保留各自关键契约 |
| 重写后采纳 | poteto-mode 路由、figure-it-out、owner/verifier、明确 stop/retry/恢复 | 去 Cursor 名称、模型 slug 与泛化外部写授权；补宿主适配、统一 run-state 和硬预算 |
| 按需使用 | arena/architect、swarm、benchmark、formal verification/statechart、skill eval、maintain verify/formal | 方法强但不应每次小变更固定跑多模型、十 live lanes、perf gate |
| 暂不原样采纳 | no-comments 的怀疑即删除、every boundary change 强 arena、固定每 PR 十 live lane、所有 prose 都仪式化处理 | 会让简单任务繁琐，造成范围扩大、删除有用注释或大量成本 |
| 暂不作为基础 | make-bot-ui、ketchup-video、Benny、清理 worktree/simulator、全自动 merge | 与常规开发目标的关联较间接，外部权限或不可逆操作较强；等具体需求再建适配和授权 |

构建顺序建议是：先在一个真实仓库做可重跑 verify 与固定 schema 的任务契约，再加独立 review 和有界修复循环，最后才接跨会话 supervisor/自动 PR/合并。先证明最小纵切能从任务到“可审阅且证据齐全”，再扩并发。pstack 自己的 orchestrate 也要求先跑通一单元再 fan out。[orchestrate](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/poteto-mode/playbooks/orchestrate.md)、[create-verification-skill](https://github.com/cursor/plugins/blob/bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7/pstack/skills/create-verification-skill/SKILL.md)。
